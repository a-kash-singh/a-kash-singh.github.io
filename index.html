Observability

groundcover · otel · grafana
  • As codeEvery alert, route and contact point in Terraform, applied by Jenkins on each PR. One teams file maps services to owners; prod pages PagerDuty, stage goes to Slack.
  • Signal, not noiseLonger default alert windows to stop flapping, scoped exclusions for scanners and telemetry paths, and per-service overrides instead of global mutes.
  • CardinalityDropped request_id in the OTel collector, capped Kong metric cardinality, and added head-based trace sampling to the shared Go service framework.
  • CoverageKong per-API status and upstream-health metrics; Airflow metrics moved from lossy StatsD/UDP to OTLP; batch-job logs routed to stdout so pipelines stopped being blind.
  • Cost of seeingA weekday ingestion-trend report on the noisiest services by log and trace volume, so growth gets caught before the invoice does.

Team release: OTP reliability & cost

aug 2026 · shared credit

OTP volume was far out of line with daily active users. We put bot detection on the public send-OTP API in monitor mode first, confirmed most of the traffic wasn't human, then switched it to block. I was one of five engineers credited in the release, and I helped on the WAF side with the bot-detection rules in front of the API.

  • WAF bot detection in front of the operator, rolled out monitor → block
  • Tighter rate limits on the OTP APIs
  • A multi-operator retry chain, so one failing route falls through to the next
  • WhatsApp as a second OTP channel

postmortems · abridged

Incidents I worked on

The ones worth retelling are the failures that didn't look like their cause. Blameless, shortened, and scrubbed of internal names and numbers.

DNSkubernetes

Unrelated services failing together

Impact
Database connections, GitOps sync and several services degraded at the same time.
Cause
One misbehaving pod made its clients retry nonstop, which saturated cluster DNS for everyone.
Fix
Fixed the workload, then pushed for node-local DNS caching to shrink the blast radius next time.
DBpostgres

High CPU with no traffic spike

Impact
Queries slowed down across the board.
Cause
Catalog statistics bloated after a large bulk delete, so query planning itself became the bottleneck.
Fix
Cleaned up the bloat instead of scaling the instance up.
IAMgo operator

Workloads losing AWS access

Impact
New tenant environments couldn't assume their IAM role.
Cause
A shared IRSA role's trust policy grew with every tenant until it hit IAM's size limit.
Fix
Collapsed entries into one wildcard per service account and added an operator sweeper with a grace period, dry-run first.
CDCkafka connect

Connectors failing after a cert rotation

Impact
Some change-data streams stopped with TLS handshake errors.
Cause
A database CA change the connector truststore didn't recognise.
Fix
Targeted config on the failing connectors only, with TLS kept on; the lasting fix is shipping the CA bundle in the image.
SCALEautoscaling

Intermittent 503s from a core service

Impact
A latency-critical dependency returned errors under normal load.
Cause
A vertical autoscaler cut its CPU request based on average use, so it throttled at peak.
Fix
Reverted, and kept latency-critical services out of automatic right-sizing until load-tested.
PERFapplication

Tail latency on one busy endpoint

Impact
Repeated P99 breaches and pressure on a shared cache.
Cause
An N+1 pattern: records were enriched before pagination, multiplying downstream calls.
Fix
Proposed: paginate first, batch the lookups, add bounded parallelism, and fold earlier partial fixes into one change.

A mutating admission webhook that right-sizes DaemonSet CPU and memory requests to each node's real capacity, using Karpenter labels or node status. Opt-in labels, min/max clamping, fail-open admission. It fills a gap cluster autoscalers leave open.
